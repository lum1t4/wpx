## Safer WordPress handoffs and coherent operations

Alpha.18 was tagged but its deployment was cancelled. This alpha.19 release
carries forward all of its user-visible changes:

- WordPress Debug writes to a private per-site log while keeping errors hidden
  from visitors. The panel reads only the newest 256 KiB and can clear the log.
- WordPress Search and replace requires an active recovery target and a fresh,
  one-use 15-minute preview. Apply creates a recovery snapshot first. A possibly
  partial failure identifies the snapshot that must be restored before retrying.
- Backup pages show up to 50 recent scheduled and manual runs, including current
  restore-point availability. Request logs add bounded IP, status, method and
  path filtering, browser copy, and formula-safe CSV download.
- Sign-in names may be usernames or email addresses. Users can rename their own
  sign-in with password confirmation; authorized administrators can rename a
  managed user without changing identity, role or grants.
- Site navigation has clearer identity and WordPress grouping. Content-derived
  static asset URLs and validators prevent Firefox from retaining mismatched CSS
  or JavaScript across upgrades.
- Plugin inventory and deactivation skip ordinary plugins and the active theme,
  so a plugin that breaks normal WordPress bootstrap can still be identified and
  disabled. Malformed inventory remains an error.

Alpha.19 also adds:

- Alert settings persist a master switch, independent Email, Slack and Telegram
  channel switches, and a condition selection for each channel. Delivery is the
  intersection of the detected condition, global rule, master switch, channel
  switch and that channel's selection. A failed channel retries after the
  configured cooldown without resending channels that already succeeded.
- Database pages use one compact list for WordPress and application databases.
  Native Create and Delete dialogs preserve the existing permissions, generated
  credentials and exact-name deletion confirmation. phpMyAdmin setup appears
  only when an authorized server manager can act on it.
- One-click WordPress login uses one trusted stable public handler and a private,
  hashed, single-use capability. The 256-bit token remains in the URL fragment,
  is POSTed by the handler, expires after 90 seconds and is claimed before
  WordPress starts. Failed or replayed handoffs require a new link.
- Alert save-state controls and concise alert condition labels are available in
  all 33 locale catalogs. Missing or unmarked interface copy still falls back to
  English; this is not a claim that every page or runtime error is translated.

Email, Slack and Telegram require operator-supplied credentials. Automated tests
use fake transports; live notification delivery was not exercised. WordPress
login uses HTTPS only when site TLS is active, requires JavaScript for the
fragment-to-POST handoff, and necessarily posts over HTTP on a non-TLS site.
Search and replace clears the site's Redis namespace; existing FastCGI pages
can remain cached until their normal 10-minute expiry.
